# Microsoft Store (MSIX) packaging

The Store edition of Phramer is an MSIX package built from a separate
configuration of the same source. The MSI and portable ZIP are unaffected.

| File | Purpose |
|---|---|
| `AppxManifest.xml.in` | Package manifest template; `make-msix.ps1` fills the `@…@` fields |
| `Assets/` | Tile and taskbar icons, generated by `generate-assets.sh` and committed |
| `make-msix.ps1` | Stages a `cmake --install` tree and packs it with `makepri` and `makeappx` |
| `sign-for-sideload.ps1` | Test-signs a copy for installing locally before submission |

## Building

```powershell
cmake -B build -G "Visual Studio 17 2022" -A x64 "-DCMAKE_BUILD_TYPE=Release" "-DUSE_PORTABLE_CONFIG=OFF" "-DPHRAMER_STORE_BUILD=ON"
cmake --build build --config Release
cmake --install build --config Release --prefix stage
./packaging/msix/make-msix.ps1 -InstallDir stage -Version 15.0.0 -OutDir dist
```

CI does the same in the `windows-msix` job of `Windows-pack.yml` (every
pull request and push to master) and of `Windows-release.yml` (every `v*`
tag). Both upload the packages as workflow artifacts, never as release
assets.

Two variants are produced:

- `Phramer_<ver>.0_x64.msix` declares the `ms-screenclip` protocol, so
  Phramer can be chosen for Print Screen and Win+Shift+S in Settings >
  Default apps.
- `Phramer_<ver>.0_x64_noscreenclip.msix` leaves it out, as a fallback if
  certification objects to the declaration. The app reads its own manifest
  and hides the ms-screenclip options when the protocol is not declared.

## Package identity

`make-msix.ps1` defaults to the values on Partner Center's Product identity
page for Store ID 9N5NN1F5FRX7:

| Field | Value |
|---|---|
| Package/Identity/Name | `Michael-Nguyen.Phramer` |
| Package/Identity/Publisher | `CN=C5782711-0775-466E-A81A-2D97D92962AD` |
| Package/Properties/PublisherDisplayName | `Michael-Nguyen` |
| Package family name | `Michael-Nguyen.Phramer_czsk4xdqz4qyg` |

They are public and must match Partner Center exactly. The version is the
CMake version plus a `.0` that the Store reserves; it must strictly increase
with every submission.

## Testing before submission

Windows installs only signed packages; the Store signs its own copy after
certification. To try a build first, take the `sideload` files from the CI
artifact (or run `sign-for-sideload.ps1` yourself), then in an elevated
PowerShell:

```powershell
Import-Certificate -FilePath Phramer_<ver>.0_x64_sideload.cer -CertStoreLocation Cert:\LocalMachine\TrustedPeople
Add-AppxPackage Phramer_<ver>.0_x64_sideload.msix
```

Each CI run makes a new throwaway certificate whose private key is deleted
straight after signing. Run the Windows App Certification Kit against the
sideload copy (WACK installs the package, and Windows installs only signed
ones; the contents are identical to the unsigned package), before
installing it by hand:

```powershell
appcert.exe reset
appcert.exe test -appxpackagepath Phramer_<ver>.0_x64_sideload.msix -reportoutputpath wack.xml
```

Upload the **unsigned** `Phramer_<ver>.0_x64.msix` to Partner Center, never
the sideload copy.

## What the Store edition changes

`PHRAMER_STORE_BUILD` turns on `DISABLE_UPDATE_CHECKER` and changes the parts
of Phramer that cannot work, or are not allowed, inside a package:

| Feature | MSI / ZIP | Store edition |
|---|---|---|
| Updates | In-app updater downloads the MSI from GitHub | Delivered by the Store; the app restarts after one |
| Print Screen key | Writes `PrintScreenKeyForSnippingEnabled` | Opens Settings > Accessibility > Keyboard for the user to switch |
| ms-screenclip | Elevated registration under HKLM | Declared in the manifest; chosen in Settings > Default apps |
| Launch at sign-in | Run key, on by default | Startup task, off until the user turns it on |
| Tray Restart | Starts the exe by path | Activates the app by its AUMID |
| Second launch from Start | Exits silently | Shows the running copy's launcher |
| `phramer-cli` | Beside the exe | On every terminal's PATH through an execution alias |

The package has a single application. Partner Center rejects an application
hidden from Start (`AppListEntry="none"`) unless Microsoft grants a
`HeadlessAppBypass` waiver, so the console alias is an extension of the main
application rather than an application of its own.

The reasons are in `docs/store/` and in `CLAUDE.md`.
